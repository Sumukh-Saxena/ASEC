### Deviations to record in `docs/PHASE7_PLAN.md` §15 at W7

- **0017 CHECK typo.** Plan §5.2 has `CHECK ((people_needed IS NULL) != (people_needed_unlimited = 1))`, which is false for the legal `OPEN, 3, 0` row. 0017 uses the valid PB-3 encoding: `people_needed_unlimited = 0 OR people_needed IS NULL`, `OPEN` iff `(people_needed IS NULL) = (people_needed_unlimited = 1)`, and `EXPLICIT` iff `people_needed IS NULL AND people_needed_unlimited = 0`.
- **Foreign-keys-off runner mechanism.** The plan expected `PRAGMA defer_foreign_keys = ON` per file while the runner kept enforcement on. With `foreign_keys = ON`, `DROP TABLE person/task/announcement` is rejected while RESTRICT children exist even inside one transaction. The runner now sets `PRAGMA foreign_keys = OFF` **before** `BEGIN`, runs the batch, runs `PRAGMA foreign_key_check` **before** `COMMIT`, and restores the caller's pragma in `finally` (`backend/db/migrations.py`, tested in `tests/test_db_migrations.py`).
- **Atomic window.** 0016–0018 are applied as one transaction (`ATOMIC_WINDOWS`), not one transaction per file: a failure in 0018 leaves `schema_migrations` at version 15 and the old `person`/`task`/`announcement` shapes intact (O7-1 pre-roster window).
- **0017 copy guards.** 0016 and 0018 implement the plan's guard `SELECT ... RAISE(ABORT, ...)` clauses as `BEFORE INSERT` triggers on the rebuilt tables. 0017 has no equivalent guard: every pre-window state the plan lists (CROSS_VERTICAL with NULL/equal responsible, EXPLICIT `people_needed` not 1, duplicate assignee pair) is already impossible under 0006's CHECK/UNIQUE constraints, so a guard could never fire. The rebuilt table's CHECKs and the partial unique index are the forward guard; this is documented in `tests/test_migrations_task_schema.py`.
