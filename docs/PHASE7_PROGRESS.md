- **Foreign-keys-off runner mechanism.** The plan expected `PRAGMA defer_foreign_keys = ON` per file while the runner kept enforcement on. With `foreign_keys = ON`, `DROP TABLE person/task/announcement` is rejected while RESTRICT children exist even inside one transaction. The runner now sets `PRAGMA foreign_keys = OFF` **before** `BEGIN`, runs the batch, runs `PRAGMA foreign_key_check` **before** `COMMIT`, and restores the caller's pragma in `finally` (`backend/db/migrations.py`, tested in `tests/test_db_migrations.py`).
